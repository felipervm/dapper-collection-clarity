DATA METHODOLOGY · INDEPENDENT EXTENSION

What the numbers
can tell you.

This client loads a player roster and collection snapshots, then requests a separate locked-score leaderboard. The disclosure in the graph reports which view you are seeing.

Collection source

The roster comes from data/index.json. The client normally tries a player JSON snapshot at fandom-v3.vercel.app and falls back to a repository sample if that request fails. The explicit sample=1 demo mode uses the local snapshot directly.

The upstream contribution guide describes generation using private BigQuery infrastructure. This extension does not query that generator or independently establish the snapshot’s on-chain completeness. The included source files are public upstream samples.

Two ranking views

Available locked score: the separate API proxy returns at most 1,000 entries. Scores are matched to loaded holders by address. A holder absent from the returned page has an unknown score, not a verified zero. The sum displayed is for returned entries.

Ownership view: if the response fails, is empty, malformed, invalid, duplicated, or cannot match the loaded holders, the collection is sorted by reported Moments owned. The UI identifies this fallback. Ownership is not a substitute estimate of locked score.

Displayed positions describe the loaded holder subset. They are not official leaderboard ranks. Accounts need not correspond one-to-one to people.

Coverage and freshness

The graph fully renders a subset of holders and reports that subset against the loaded holder count. Existing system-address and large unnamed-wallet filters are retained; they are heuristics, not a perfect classification of fans.

Edition spotlight matches come from observed serials. Absence from those serials is not proof that a holder lacks an edition. A partial flag is disclosed; absence of that flag is not an independent completeness guarantee.

Source update time is shown when supplied by the supported metadata fields. If it is absent, the disclosure says so. Request time is not presented as snapshot freshness.

Verification

The recorded audit checks the three included samples. Its count reconciliation runs independently in Python and SQL. The sprint notes record the reviewed upstream commit, tests and remaining limits.
